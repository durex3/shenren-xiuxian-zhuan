# 开发计划

## 一、交付目标

首个里程碑是可完整体验第一章的单机版本：创建角色、探索、接任务、战斗、引气修炼、加入外门、保存、重新加载并继续。长期功能逐步扩充，不要求首次交付全部完成。

当前只完成设计文档。以下代码阶段均未开始，不以目录或按钮存在作为功能完成标准。

## 二、实施顺序与验收

| 阶段 | 状态 | 交付内容 | 验收标准 |
| --- | --- | --- | --- |
| 0 设计基线 | 已完成 | 需求、架构、计划、美术规范 | 已确认规则与默认方案清楚区分 |
| 1 可运行骨架 | 未开始 | Vite、Phaser、启动加载菜单、设置、占位资源、横屏适配 | 电脑与手机尺寸能启动；加载失败可重试；构建产物经 HTTP 可访问 |
| 2 创建与探索 | 未开始 | 自定义角色、五行灵根、一张测试地图、碰撞与键鼠触屏输入 | 角色不穿墙；点击寻路和摇杆可用；交互与 UI 不抢输入 |
| 3 回合战斗 | 未开始 | 独立战斗、双方阵位、速度排序、六类指令、灵力怒气、胜负逃跑 | 覆盖单人及 5 对 5；死亡单位不行动；结算只发一次；战败正确返回 |
| 4 任务与物品 | 未开始 | 对话、任务链、采集、宝箱、背包、基础装备法宝、传送 | 任务可接可交；资源和物品正确变化；首章教学流程可走通 |
| 5 修炼与持久化 | 未开始 | 历法、闭关、顿悟、炼气小层提升、存档版本与备份 | 暂停和后台不走时；离线不推进；小层提升正确；重载数据一致 |
| 6 第一章闭环 | 未开始 | 三张区域地图、秘境首领、章节任务、外门入门结算 | 新存档可从凡人推进至炼气三层并加入外门，存档继续可用，无强制刷取造成的流程死锁 |
| 7 美术与发布 | 未开始 | 接入作者素材、音效、手机布局优化、性能检查 | 无缺图、遮挡和触屏死区；资源授权信息齐全；输出静态发布包 |
| 8 后续内容 | 未开始 | 伙伴灵兽、完整炼丹炼器、宗门关系、更多章节与灵根变化 | 每次按一个可玩模块单独设计与验收 |

存档状态结构从阶段 1 预留，最小保存从阶段 2 接入；阶段 5 完成迁移、恢复与备份。队伍结构从阶段 3 支持五人，招募内容在后续阶段开放。美术若提前到位，可在各阶段逐步替换，不必等到阶段 7。

## 三、首版内容约束

- 第一章完成基础修仙闭环：角色与灵根、炼气修炼、基础战斗、功法、背包装备、丹药与基础炼丹、赤玉灵蛛、任务探索、历法和存档均需可实际使用。
- 后续系统遵循随剧情逐步解锁、已有进度跨章节继承的原则；本计划不提前规定后续章节的系统清单和开放顺序。
- 先实现五种灵根的数据与明显效果差异，每种至少有一项可体验的对应功法。
- 六类战斗指令均有实际功能，不能用未实现按钮冒充完成；法宝可先提供一个基础实例。
- 三张主地图、主线七步、三条支线和一个首领；NPC、敌人、技能数量以支撑该流程为准。
- 基础丹药先可获得和使用；首版加入一个可完成的炼丹配方，复杂炼丹、炼器与经营后续扩展。
- 自动战斗和倍速在手动战斗稳定后补齐，优先保证核心指令和结算可靠。

## 四、验证方式

规则测试重点覆盖速度与同速排序、目标阵位、伤害和资源边界、任务幂等领奖、炼气小层提升、外门核验条件、历法跨月与存档迁移。

浏览器流程覆盖创建角色到第一次战斗、任务领奖后重载、战败回安全点、闭关后存档、手机触屏操作。美术接入后检查截图、贴图加载和不同屏幕布局。

性能初始目标为桌面 60 FPS、目标手机稳定 30 FPS 以上；这不是当前已达到的结果。确定实际测试设备后测量加载耗时、内存与帧率，记录资源预算。连续切换地图与战斗时检查监听器、计时器和内存是否持续增长。

## 五、阶段交付格式

每阶段提供：通俗设计说明、实际代码及中文注释、启动与验证结果、主要文件作用、配置修改示例、已知限制。新增需求记录到设计文档，影响工期或前置依赖时同步更新本计划。

下一步为阶段 1：先建立能在浏览器运行的工程骨架，使用可替换的临时素材，不等待最终美术。
