# 美术资源规范

美术由作者后续制作。以下是建议规格，正式批量绘制前用一套样例验证尺寸、锚点与动画效果，避免返工。参考截图用于沟通画风，不作为直接裁切发布的素材。

## 一、视觉方向

- 大地图：淡彩水墨、清楚的山石树木轮廓、较大可行走留白，小比例 Q 版角色。
- 宗门与地标：山水建筑绘景，入口和交互位置独立配置。
- 战斗：侧向站位，较大的人物或灵兽形象，水墨背景保证前景辨识度。
- UI：古朴图标与适度墨迹装饰；信息文字由代码渲染，便于数值变化与手机适配。

## 二、推荐交付规格

| 类别 | 初始建议 | 必要说明 |
| --- | --- | --- |
| 探索角色 | 透明 PNG，单帧 128×128，4 方向行走各 4 帧，另有待机帧 | 同角色帧尺寸统一，脚底中心锚点固定 |
| 战斗角色 | 透明 PNG，建议 512×768 | 保留完整身体、武器和特效边缘；统一朝向并注明是否允许镜像 |
| 头像 | 256×256 PNG | 与角色外观 ID 对应 |
| 地表图块 | 64×64 PNG 或图集 | 无缝拼接；地图逻辑格尺寸与图片显示尺寸分离 |
| 山石建筑 | 独立透明 PNG，按实际比例绘制 | 标明落地点、遮挡范围和入口位置 |
| 战斗背景 | 1920×1080 PNG/WebP | 中央留出双方站位区域，兼容宽屏裁切 |
| 大地图绘景 | 按区域绘制，建议拆为不大于 2048×2048 的块 | 配套通行和遮挡数据，不用一张超大图承载整个世界 |
| 道具技能图标 | 128×128 透明 PNG | 边距统一，在较小显示尺寸下仍能辨识 |
| 面板与按钮 | 透明 PNG，可九宫格拉伸 | 不把动态文字烘焙进图片；注明不可拉伸边距 |
| 特效序列 | 建议单帧 256×256，统一帧尺寸 | 附帧率、播放次数、锚点及混合方式 |

以上是源素材建议，不等于屏幕显示像素。游戏会按逻辑尺寸缩放，后续根据手机清晰度与资源体积调整。

## 三、目录和命名

资源放到 public/assets 对应分类。文件名使用小写英文、数字和下划线，例如 player_male_01_walk.png、qinglan_path_01.webp、skill_fire_01.png。

资源清单记录稳定资源 ID、路径、帧尺寸、锚点和逻辑显示尺寸。代码只使用资源 ID；替换文件或调整清单即可更新素材。

每批资源附说明表：文件名、用途、原始尺寸、帧顺序、朝向、锚点、是否可镜像、作者或来源、使用许可。原始 PSD 等工程文件由作者单独保管，不放入浏览器发布目录。

## 四、地图如何变得可玩

地图画面之外还需要可行走范围、碰撞区域、建筑遮挡、出生点、NPC、传送点和剧情触发区。开发时使用 Tiled 对象层等结构化数据标注，并提供样例，不要求作者把碰撞逻辑画进图片。

可先交付一名角色、一张小地图和一套图标进行接入验证。最终美术到位前使用明确标记的临时素材，其资源键、帧规格和正式素材保持一致；替换后重新检查碰撞、脚底对齐及 UI 清晰度。

## 五、赤玉灵蛛现有动画约定

- 战斗待机使用一张基础姿势；普通攻击与防御各使用两张关键动作图，并与待机图组合过渡。这是预期的简帧表现，不视为缺帧。
- 受击使用三张独立动作图，顺序为命中、失衡、击退，结束后返回待机。
- 技能施法复用普通攻击的身体动作。不同技能单独配置释放特效、弹道、命中特效、音效和数值时机，不为每个技能重复制作身体动画。
- 探索行走原始资源只制作北、东北、东、东南、南五个方向。西北、西、西南分别水平镜像东北、东、东南；对应待机图使用相同映射。
- 镜像只作用于显示贴图，不改变逻辑移动方向、脚底锚点、碰撞体或交互范围。
- 战斗死亡使用四张身体动作图，依次表现下沉、倒地、蜷缩和最终姿态；结束后保持最终姿态并叠加四张赤色灵光消散特效，角色随特效逐渐隐藏，不返回待机。
